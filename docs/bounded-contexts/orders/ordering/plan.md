## Canvas summary
Ordering lets a customer prepare an order of items, with the order total capped at 100 PLN and at most 3 items of each item type. It is a **core** domain with a **revenue** business model, **custom built**. Its role is **Execution Model**.

### Business rules → aggregates
All rules guard the same state (the items of one order), so they belong in one `Order` aggregate. Test class: `src/test/java/.../orders/ordering/domain/order/OrderTest`, written one scenario at a time (D3).

| Rule (GWT) | Invariant | Aggregate | Test |
|---|---|---|---|
| R1a: given an empty order, when an item for 100 PLN is added, then the item is added | order total ≤ 100 PLN | `Order` | `OrderTest#itemForExactly100PlnFitsIntoEmptyOrder` |
| R1b: given an order with items totalling 90 PLN, when an item for 20 PLN is added, then adding the item is rejected | order total ≤ 100 PLN | `Order` | `OrderTest#itemPushingTotalAbove100PlnIsRejected` |
| R2a: given an order with 2 "Helmet" items, when another "Helmet" is added, then the item is added | ≤ 3 items per item type | `Order` | `OrderTest#thirdItemOfTheSameTypeIsAdded` |
| R2b: given an order with 3 "Helmet" items, when another "Helmet" is added, then adding the item is rejected | ≤ 3 items per item type | `Order` | `OrderTest#fourthItemOfTheSameTypeIsRejected` |
